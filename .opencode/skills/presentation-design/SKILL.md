# Оформление презентации

## Когда использовать

- Нужно выбрать макет для слайда или переделать существующий.
- Нужно поменять цвета, шрифты или логотип.
- Нужно проверить готовую презентацию на перегруз, переполнение и единообразие.

## Источник оформления

Единственный источник цветов, шрифтов и логотипа — `templates/default/theme.yaml`.
Никогда не задавай цвета и размеры шрифтов в `deck.yaml`: их там нет.
Поменял `theme.yaml` → пересобери шаблон и презентацию:

```bash
python3 scripts/build.py --refresh-template
python3 scripts/build.py decks/<папка>
```

## Порядок работы

1. Прочитай `templates/default/theme.yaml` и `references/layouts.md`.
2. Для каждого слайда выбери макет по смыслу, а не по красоте:
   - тезисы → `bullets`, сравнение → `two-col`, 2–4 равноправные идеи → `cards`,
     процесс → `steps`, числа → `table`, код → `code`, схема/фото → `image`,
     итоговый конспект → `summary`.
3. Сформулируй заголовок как утверждение, а не как тему: «Пузырьковая сортировка
   медленная на больших данных», а не «Сортировка».
4. Проверь слайд по `references/checklist.md`.
5. Собери и посмотри результат глазами (PPTX/PDF/HTML), а не только по коду.

## Иллюстрации

Если нужна схема, процесс, массив, дерево или логическая цепь — не рисуйте
её вручную в PowerPoint. Используйте скилл `presentation-illustrations`:
сцена описывается в YAML, собирается в PNG и подключается через макет `image`.
Это даёт единый стиль и возможность быстро поменять палитру.

Правила те же: одна мысль на картинку, подпись объясняет вывод, заголовок
слайда не дублируется внутри изображения.

## Жёсткие правила

- Один слайд — одна мысль. Если мыслей две, это два слайда.
- Титул: общая тема + уточнение (подзаголовок), класс и год. Без фамилии
  и имени — презентацию показывает учитель.
- Не делай отдельный слайд-раздел вторым после титула: уточнение темы
  уже есть в подзаголовке.
- Последний слайд — опорный конспект (`summary`), а не «Спасибо за внимание».
  Титул и финал остаются тёмными, остальные слайды — светлые.
- Не делай слайд из одной цитаты: цитата идёт в тезис или в `notes`.
- Слайд только с цитатой не ставим: цитата либо подтверждает тезис, либо уходит
  в заметки. Цитата ради настроения — не слайд.
- Заголовок: до 70 знаков, максимум 2 строки.
- Тезисы: до 7 пунктов, до 12 при `columns: 2`; вложенность — максимум 1 уровень.
- Текст тезиса: до 140 знаков. Длиннее — сокращай или выноси на отдельный слайд.
- Код: до 18 строк и до 60 знаков в строке. Длинный код сокращай до сути.
- Таблица: до 7 строк и 5 столбцов.
- Карточки: 3 (реже 2 или 4), одинаковой высоты.
- Не ставь два акцентных элемента рядом: акцент должен быть один на слайд.
- Не используй CAPS для целых абзацев — только для коротких надзаголовков.
- Логотип не перекрывает заголовок: заголовок уже ограничен макетом.
- Изображения — только PNG/JPG, с подписью и по делу. SVG в PPTX не встраивается.
- Не украшай слайд «для красоты»: декор уже есть в шаблоне.

## Типографика

Размеры подбираются автоматически, но ориентиры такие:

| Элемент | Размер |
| --- | --- |
| Заголовок слайда | 26–32 pt |
| Заголовок раздела / титула | 40–46 pt |
| Тезисы | 18–20 pt |
| Подзаголовок, лид | 15–17 pt |
| Подписи, сноски | 11–13 pt |

Не уменьшай шрифт вручную ради того, чтобы влезло: лучше сократить текст.

## Логотип и фирменные цвета

- `logo.file` — версия для светлых слайдов, `logo.file_dark` — белая версия для
  титула, разделов и финала.
- Формат — PNG с прозрачным фоном, квадратный или горизонтальный.
- Ширина задаётся в `logo.width` (дюймы). По умолчанию 0.62.
- Цвета меняй только в блоке `colors`. После правки проверь контраст: текст на
  фоне должен читаться при печати в чёрно-белом виде.

## Проверка

Перед сдачей пройди `references/checklist.md`. Если что-то не сходится —
исправляй содержимое, а не подгоняй шрифт.
