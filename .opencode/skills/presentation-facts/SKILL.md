# Проверка фактов и корректности данных

## Когда использовать

- В слайдах есть определения, формулы, сложность алгоритмов, единицы измерения.
- Есть исторические даты, имена, названия стандартов и версии.
- Есть код, таблица истинности или числовой пример.
- Утверждение звучит как «самый быстрый», «всегда», «учёные доказали».

## Главный принцип

Каждое проверяемое утверждение получает один из трёх статусов:

| Статус | Что делаем |
| --- | --- |
| Проверено | Оставляем на слайде, источник — в `notes` |
| Спорное | На слайд не выносим или смягчаем формулировку, разбор — в `notes` |
| Не проверено | Либо проверяем, либо убираем. Третьего нет |

Не бывает «наверное, правильно». Если проверить нельзя (нет источника, нет
времени) — утверждение уходит со слайда.

## Порядок работы

1. **Выпиши утверждения.** Пройди слайды и выпиши всё проверяемое: определения,
   формулы, числа, даты, имена, строки кода.
2. **Разложи по типам.** Определение / формула / число и единица / дата и имя /
   код / цитата. У каждого типа свой способ проверки — см. ниже.
3. **Проверь по первичному источнику.** Стандарт, документация, статья автора,
   учебник — в этом порядке. Пересказ в блоге источником не считается.
4. **Запусти то, что запускается.** Формулу — на всех входах, код — целиком,
   таблицу истинности — перебором.
5. **Зафиксируй результат в `notes`.** Коротко: что проверено и где.
6. **Собери и убедись, что пометки не попали на слайд.** `notes` не выводятся.

## Как проверять по типам

### Определения

- Сверяй с учебником, по которому идёт класс, а не с первым результатом поиска.
- Проверь, что определение не подменено метафорой: «процессор — мозг компьютера»
  это объяснение, а не определение.
- Если определений два и они спорят между собой — это два слайда или один
  из них лишний.

### Формулы

- Подставь граничные значения: `n = 0`, `n = 1`, пустой список, отрицательные числа.
- Для логических формул построй таблицу истинности перебором всех входов —
  это быстрее и надёжнее, чем рассуждать.
- Проверь приоритет операций и скобки: `¬A ∧ B` и `¬(A ∧ B)` — разные вещи.

### Числа и единицы

- Переводи единицы явно, в одну строку: `10 МБ = 10 · 8 = 80 Мбит`.
- Различай `Кбайт` (1024 байта) и `кБ` (1000 байт), `Мбит/с` и `Мбайт/с`.
- Степени двойки пиши точно: `2^10 = 1024`, `2^20 = 1 048 576`, `2^32 = 4 294 967 296`.

### Даты, имена, версии

- Две независимые ссылки, приоритет — первичная публикация или документация.
- Год события и год публикации — разные вещи: «изобрёл» и «опубликовал» не одно и то же.
- Не пиши «в 90-х» там, где нужен год: размытая дата читается как ошибка.

### Код

- Запусти код целиком, а не «глазами». Python 3, без внешних библиотек.
- Проверь, что пример не зависит от версии: `print` со скобками, `input()` даёт строку.
- Если код на слайде сокращён ради места — в `notes` укажи, что именно убрано.

### Цитаты

- Цитата — только дословно и с автором. Пересказ оформляй как пересказ, без кавычек.

## Куда писать результат

Поле `notes` слайда — заметки докладчика, на слайд не выводятся:

```yaml
- layout: bullets
  title: "Числа с плавающей точкой неточные"
  bullets:
    - "0.1 + 0.2 даёт 0.30000000000000004"
  notes: >-
    [проверено 2026-11-06] Проверено запуском в CPython 3:
    0.1 + 0.2 == 0.3 → False. Источник:
    docs.python.org/3/tutorial/floatingpoint.html
```

Для спорного утверждения:

```yaml
  notes: >-
    [спорно] «первый компьютер»: Z3 (1941), Colossus (1943), ENIAC (1945–46).
    Критерий не задан — на слайде формулировка «один из первых».
```

Разметка пометок:

- `[проверено ГГГГ-ММ-ДД]` — дата проверки и источник;
- `[спорно]` — что именно спорно и почему;
- `[оценка]` — утверждение без факта, требует переформулировки.

## Спорное и оценочное

Оценочные утверждения не проверяются, их можно только переформулировать:

| Плохо | Лучше |
| --- | --- |
| «Python — самый быстрый язык» | «Python короче в записи, но медленнее C на численных циклах» |
| «Быстрая сортировка всегда O(n log n)» | «В среднем O(n log n), в худшем O(n²)» |
| «Wi-Fi — это интернет» | «Wi-Fi — технология беспроводной локальной сети» |
| «Бит — это 0 или 1» | «Бит — выбор из двух равновероятных вариантов; 0 и 1 — запись» |
| «Учёные доказали, что…» | Конкретная работа, автор и год — или утверждение убирается |

Если слайд разваливается без спорного утверждения — переделывай слайд,
а не факт.

## Что проверять в первую очередь

Разбор типовых ошибок по темам — `references/checks.md`: сложность алгоритмов,
единицы информации, системы счисления и кодировки, алгебра логики, поведение
Python, устройство компьютера, сети, исторические даты.

## Чек-лист перед сборкой

- [ ] На каждом слайде с числом или формулой есть пометка в `notes`.
- [ ] Все даты и имена сверены с первичным источником.
- [ ] Код запущен, вывод совпадает с тем, что на слайде.
- [ ] Нет «самый», «всегда», «все» без оговорки.
- [ ] Спорное вынесено в `notes`, а не на слайд.
- [ ] В `meta` нет `author` с именем и фамилией.

## Запреты

- Не придумывать источник, дату и цифру — даже «похожую».
- Не подгонять факт под красивую схему: переделывается схема.
- Не писать «исследования показывают» без конкретной ссылки.
- Не оставлять пометку «проверено» без даты и источника.
